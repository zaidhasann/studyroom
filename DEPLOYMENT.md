# Deployment Guide

## Prerequisites

- GitHub repository with the project
- MongoDB Atlas account
- Vercel account
- Render account

---

## 1. Setup MongoDB Atlas

### Create Database

1. Go to [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)
2. Create a new project or use existing
3. Create a Cluster (Free tier available)
4. Choose cloud provider and region
5. Click "Create Cluster"

### Create Database User

1. Click on "Security" > "Database Access"
2. Click "Add New User"
3. Choose "Autogenerated Secure Password"
4. Copy the password and save securely
5. Set user privileges to "Read and write to any database"
6. Click "Add User"

### Allow Network Access

1. Click on "Security" > "Network Access"
2. Click "Add IP Address"
3. For development: Add your IP
4. For production: Add 0.0.0.0/0 (or specific IPs)
5. Click "Confirm"

### Get Connection String

1. Click on "Clusters" > "Connect"
2. Choose "Connect your application"
3. Copy the connection string (URI)
4. Replace `<password>` with your database user password
5. Replace `myFirstDatabase` with `study-room-db`

Example:
```
mongodb+srv://username:password@cluster.mongodb.net/study-room-db?retryWrites=true&w=majority
```

## 2. Deploy Backend on Render

### Prepare Repository

1. Push your code to GitHub
2. Ensure `backend` folder contains:
   - `package.json`
   - `server.js`
   - All necessary files

### Create Render Web Service

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click "New +" > "Web Service"
3. Connect your GitHub repository
4. Select the repository
5. Configure:
   - **Name:** `study-room-api`
   - **Environment:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Region:** Choose closest to you
   - **Instance Type:** Free (or Starter)

### Set Environment Variables

In Render dashboard, add these environment variables:

```
MONGO_URI=mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/study-room-db
JWT_SECRET=your_super_secret_key_generate_random_string_min_32_chars
CLIENT_URL=https://your-frontend-url.vercel.app
NODE_ENV=production
PORT=10000
```

### Deploy

1. Click "Create Web Service"
2. Render will automatically build and deploy
3. Wait for deployment to complete
4. Note the URL (e.g., `https://study-room-api.onrender.com`)

> **Note:** Free tier sleeps after 15 minutes of inactivity

## 3. Deploy Frontend on Vercel

### Prepare Repository

1. Ensure `frontend` folder structure is correct
2. Update `.env.production` (create if not exists):

```
VITE_API_URL=https://your-backend-url.onrender.com
VITE_SOCKET_URL=https://your-backend-url.onrender.com
```

### Connect to Vercel

1. Go to [Vercel Dashboard](https://vercel.com/dashboard)
2. Click "Add New..." > "Project"
3. Import GitHub repository
4. Select repository
5. Configure:
   - **Framework Preset:** Vite
   - **Root Directory:** `frontend`
   - **Build Command:** `npm run build`
   - **Output Directory:** `dist`

### Set Environment Variables

In Vercel project settings:

```
VITE_API_URL=https://your-backend-url.onrender.com
VITE_SOCKET_URL=https://your-backend-url.onrender.com
```

### Deploy

1. Click "Deploy"
2. Wait for build and deployment
3. Get your frontend URL (e.g., `https://study-room.vercel.app`)

---

## 4. Update Backend CLIENT_URL

After frontend deployment:

1. Go to Render dashboard
2. Go to your backend service
3. Update environment variable:
   ```
   CLIENT_URL=https://your-frontend-url.vercel.app
   ```
4. Service will redeploy automatically

## Troubleshooting Deployment

### Backend Won't Start on Render
- Check "Logs" section
- Verify environment variables are set
- Ensure port is 10000 for Render
- Check package.json has correct start script

### Frontend Shows "Cannot reach backend"
- Verify VITE_API_URL is correct
- Ensure backend is running
- Check CORS is enabled on backend
- Verify Socket.IO connection URL

### WebSocket Connection Fails
- Ensure VITE_SOCKET_URL matches backend
- Check browser console for specific error
- Verify backend supports WebSocket for your provider

### Database Connection Error
- Verify MONGO_URI format
- Check IP whitelist on MongoDB Atlas
- Ensure database user has correct permissions
- Test connection string locally first

## Security Checklist

- [ ] All secrets use strong, random values
- [ ] JWT_SECRET is at least 32 characters
- [ ] CORS only allows your frontend URL
- [ ] Database credentials not visible in logs
- [ ] HTTPS enabled on both frontend and backend
- [ ] Security headers configured
- [ ] Database backups enabled
- [ ] Monitoring and alerts set up
